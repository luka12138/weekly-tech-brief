# 每周科技巨头简报

适用包含 `reports/`、`state/supply_graph_baseline.json` 和 `docs/point_in_time_policy.md` 的周报仓库。目标是每周一交付有证据的AI公司近况报告，不是信息全集或零遗漏审计。2026-09-09用户最新固定口径：12家公司，每家公司0-5条最重要的独立事项，不凑数；先筛选，再深入核证，完成入选内容即收尾。

## 入口与权限

- 只在“每周科技巨头晨间简报”任务和原定时器内继续；另两个任务只作归档追溯。不新建任务、重复调度或为省缓存更改模型/推理设置。按用户选择只由当前模型顺序核验，不启用子代理，不冒称独立复核。
- 审计、规则维护、历史修订不自动授权提交推送、删除或替换旧产物。例行新一期发布仅按已有授权、通过全部闸门后执行；保护用户副本、凭据和无关改动。
- 用户较新的明确决定优先；查 `docs/rule_decisions.md` 当前决定，仍有实质冲突再问。不把一次性操作当永久授权，也不把用户已明确的固定规则误作单期例外。财新会员/Safari接入已取消，不恢复账号或读取凭据。
- Windows生成、Mac经GitHub查看是部署目标，不是当前主机或发布成功的证明；不擅自迁移主机、周期、任务或模型。

## 按需读取

每轮按项目入口读本skill、`docs/point_in_time_policy.md`、`docs/weekly_brief_template_v2.md`、`docs/verification_manual.md`、`docs/research_coverage.md` 和 `docs/task_consolidation.md`；同轮未变内容不重复全文加载，所需细节缺失时补读。时点/事实规则只维护于时点规范，覆盖契约只维护于覆盖规范；共性故障及验收边界见手册“共性故障与验收”。

生产/补跑读上期正文和活跃事项；规则维护只展开受影响材料，不自动重跑周报。供应/年度产品基线用 `scripts/brief_context.py --file PATH` 先列完整索引，按完整文件哈希展开所有变更、当周相关、弱证据/未知/受限记录；没有可靠已读基线或不能界定范围就分批读全量。不能只按changed标记过滤，全量校验仍读原JSON。

首次或执行规则变更时读 `docs/context_efficiency.md`；使用工具适配器时读 `docs/tool_output_contract.md`。自动化memory只读最新完整条目，历史对话/原始日志按具体缺口定位，不重新倾倒三个任务全文。

## 九项执行规则

1. **有限筛选，保留官方渠道。** 生产/补跑必须联网；12家公司各查官方当周入口，并用独立媒体或机关入口作一轮重要性校准，监管不能仅依赖公司自宣。来源路由见 `docs/research_source_routes.md`，业务专页按入选事项需要展开，不逐产品乘六类事件打满覆盖格。监管线索与活跃事项仅在可能改变本期入选或判断时定向复查。记录实际范围与受阻，不把有限检查写成全公司无事。
2. **先排重要性，再核入选事实。** 按业务/竞争影响、财务与资本承诺、关键产品和供应约束、监管经营资格及治理变化排序，每家公司最多5个独立事项。相同事件合并，独立事项不能打包绕限，不能为填满5条继续搜索。未入选材料保留理由和未决状态，不必全部补证或塞进附录；按覆盖规范标记deferred，不冒称不重大或已核完。入选内容关键缺口、会推翻本期结论的已知矛盾仍阻断相关结论；修正或如实限定后再发布，不能靠挪出清单掩盖。
3. **断言不得超出原文。** 至少一项来源直接支持每个重大事实，重大/争议/供应关系尽量双源。媒体报道、匿名消息、公司自测和观点明确归因，不当作独立确认。读具体正文、原表与脚注，官方页内AI摘要、标题、关键词命中或HTTP成功不作事实证明。逐项保留财务期间/分部/币种/单位/实际或指引、交易对价组成、适用地区/账号/版本、价格与数据保留限制。区分当事人主张、机构意见、裁判及生效状态；核清谁对谁提出什么，不能因压缩颠倒角色。复合段落拆成可分别核验的claim，未知就写未知，不补猜数值或产品型号。
4. **时间精度与版本均须有依据。** 窗口为报告周一上海00:00前一整周，截止排他；周一生成中新增信息不纳入。公开、发生、财报期、页面更新、读取和修订时点分开；不倒填retrieved_at或用文件名证明已发布。只用已公开的具体版本；原文仅日期且未知时区时按时点规范保留全球50小时完整区间，整段须合格。日末、假定午夜、数学边界不是实际发布时间。滚动正文、推荐栏分别定位，旧闻作背景，预览/计划/未交割不写成GA/实现/交割；更晚财务重列不回填为更早已知。
5. **当批落盘并当批检查。** 每批候选即时写唯一coverage账，原文/回执和claim分别定位复用，不等成稿后补证据。工具返回前验类型及合计载荷，用 `scripts/tool_output.cjs` 的 `prepareToolBatch` 保留完整日期、表头、脚注、否定和限制；超长先落盘/索引再按完整语义块读，未知结构或截断不冒充完整结果。持久化后回读核对ID、非空result、引用、字段枚举和真实时间；从工具取得URL，不拼标题猜路径。保存失败就修本地记录，不重抓已取得原文；详细持久化验收见工具契约。
6. **一次纠错，复核所有依赖。** 更正claim时检查引用它的头条、公司表、详情、行业判断、催化、供应E及产品P/PX边；反例推翻覆盖结论时重开受影响范围。稳定ID与明确映射优先于事件顺序或模糊文本匹配；自动映射、旧claim继承和区间转换均只作待审材料。正文或事实源变更后重做受影响语义复核及最终哈希绑定，不仅换哈希。旧稿、错误证据和失败回执保留追溯，迁移器不得复活已纠正错误。
7. **按依赖顺序推进，不用局部成功放行。** 正文先预检，证据/覆盖通过后再做正式图谱与来源审查，最后完整闸门和发布回执。格式、目标130/130之类数量、图能显示、测试通过都不等于事实或覆盖完成。外部受阻单列恢复条件，用户无原件不重复索取；无新定位或访问条件变化不原样重试。继续其他可完成工作，内部未完成项不能归咎于外部限制；最终仍不合格就明确草稿和全部剩余项。
8. **完成入选核证即停止。** 一轮官方筛选和独立重要性校准后冻结本期名单，只为入选事实的具体缺口补证；不因新线索重启全公司泛搜，不要求所有旧候选和活跃事项清零。已解决就转本地绑定。保留例行生产、额外补证、维护及失败返工完整token总账，用 `scripts/measure_run_tokens.py` 计量；本次改变了研究范围，不与旧全量审计混称同口径降耗。目标是减少不必要上下文，不是降低缓存命中率；入选事实证据标准不变。
9. **规则改造与生产验收分开。** 同类失败优先改共同入口/契约，不为每条新闻追加特例或重复文档。核对skill、规范、模板、手册、脚本和原自动化引用；历史裁决标明被谁替代。修改后做有针对性的回归和适用完整检查，报告实际失败，不改测试或伪造ready维持绿色。文档已更新、已知案例回归通过、真实整期可用及降耗分别报告；未做前瞻/独立复核不能冒称已做。

## 固定输出

- 中文Markdown，研究判断而非新闻堆积；品牌、代码和机器字段保留必要原文。现行12家：Apple、Microsoft、Alphabet / Google、Amazon / AWS、Meta、NVIDIA、Tesla、OpenAI、Anthropic、Samsung Electronics、SK Hynix、TSMC。历史10家公司不倒灌后来扩展对象。
- 每家公司最多5条重要事项，按实际数量列出；头条最多12条，只从各公司已入选事项提炼，不新增第二套事件。其余正文、催化和图谱也不能藏入第六条独立消息。
- 公司表覆盖12家；无合格入选信息时写“本期未筛选到经核实的重要更新”，并说明有限检查范围，不断言公司没有变化。每事件保留日期、事件、投资影响、影响指标、预期差、验证条件、可信度、来源八字段，简写但不删限制；无同口径预期就写暂不可验证。
- 取消旧“所有重大事项都须入详情/按数量无限扩篇”。总行数和字符数仍不设硬上限，以完整说明入选事项为准。第4节仅提炼已有事实，第5节最多5项已有事项的后续验证，第6节图谱只更新本期已核关系。

## 图谱与发布

两类Obsidian网络图：年度主营产品上下游、周度供应关系。JSON为事实源，JSON Canvas 1.0与同源SVG为显示层，不恢复Mermaid或完整关系Markdown表。产品具体、方向明确、Edge ID稳定、证据分级；双向互联不画成单向采购，计划采用/未来供能不画成已交付，弱关系不因沿用升级。

先完成适用的正文预检和时点证据，再运行 `scripts/plan_graph_updates.py`：供应图实质新增/强化/弱化/风险时生成；年度产品图季度首周一或实质变化时生成，其余引用原图。图例与no_new/证据等级一致；Canvas ID/边引用有效、网格对齐、节点无重叠；实际查看SVG，复杂说明留正文/JSON。6.2只列变化边，6.3解释与上周差别；基线不足明示，历史只用该期冻结JSON。

生产命令按手册顺序执行：
- `scripts/validate_weekly_brief.py --preflight-only --report PATH --baseline PATH`：初稿及每次修改后只读格式预检。
- `scripts/validate_point_in_time.py --inventory --report PATH --baseline PATH --inventory-output NEW_PATH`：完整目标直接落新文件，不用截断终端文本绑定。
- 按时点规范完成 `logs/YYYY-MM-DD_temporal_evidence.json`、覆盖闭环及财务口径/来源版本/产品图/报告版本四项实际语义复核；暂存证据显式draft，不能强行转ready。
- 通过时点校验，按图表计划生成/沿用，执行来源审查、`scripts/run_quality_gate.py` 和相关测试。2026-09-14起新稿强制逐条证据；旧稿legacy_unverified不是回测认证。
- 仅依当前授权发布，并核对真实commit/远端回执；失败保留草稿，不能将本地写入说成GitHub同步。

## 审计与历史修订

审计区分已证实越界、可得性未明、旧闻/日期错误、数值错误，给受影响位置和具体证据，不按模型代际归罪。修订记录真实创建/修订时间、原提交、更正及影响，禁止把事后重建当原周一回测输入。

用户明确要求替换时，先归档原报告、图谱、状态和日志，并登记 `state/report_vintages.json`；全部适用闸门通过后才替换。定点更正未完成全量取证的遗留稿仍是legacy_unverified；历史只读审查用 `run_quality_gate.py --historical --report ...`，不得借历史豁免发布新修订或用今日图谱回填旧期。未完成项写入唯一交接，不删除历史记录，不自动提交推送。
