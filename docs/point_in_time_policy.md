# 时点与事实核验规范

版本：1；制定日期：2026-09-07。适用于本仓库周报及图谱的生成、补跑、修订、审计和回测。

**只能使用截止时点已经公开的那一版信息；不知道何时公开，就不能认定当时已知。**

本文件是时点规则的唯一维护正文。skill、项目入口、模板、手册和自动化均引用本文件。模型代际、记忆、链接可达和旧闸门通过都不是事实保证。

2026-09-09用户允许的未确认线索隔离按`research_coverage.md`执行：只放修订核验附录，不计入当周事实、投资判断或图谱，不作为当时已知或回测输入。未知公开时点不因此获得认证；入选重大事实缺口仍阻断相关断言；2026-09-09最新筛选范围以research_coverage为准，未入选项不要求全部查完。

## 八条硬规则

1. **先定截止点，再查新闻。** 周报文件日期为周一 D；窗口为 `[D-7天 00:00, D 00:00)`，统一 Asia/Shanghai。周一生成期间出现的新消息也属于下一期，不能混入上周。
2. **按具体断言首次公开时间归周。** 事件发生日、财报所属期、网页发布日期、网页更新时间和抓取时间是不同概念。旧事件在本周首次披露，可以报道“本周披露”；旧公告被重读、转载，不是本周新进展。
3. **日期未知不放行。** URL 年月、搜索摘要、HTTP 200、Last-Modified、关键词命中、同一 URL 曾通过和模型记忆，不能单独证明断言在截止前可得。补找带日期的原始公告、监管文件、逐日更新条目或历史存档；仍无证据则列入待核验/排除记录，不能进入已确认头条或新增供应边。
4. **滚动页面核对到段落版本。** changelog、新闻列表、产品页、月营收表和带补充的公告必须定位具体日期条目。页面早发不代表全部内容早已存在；页面晚改也不自动意味着引用了未来信息。不能定位历史段落时，结论是“无法排除”，不是“通过”。
5. **预测不等于结果。** 截止前已公告的未来上市、财报日、建设计划可作为预测/催化，保留“计划/预计/将”。不得提前写成已上市、已投产、已实现收入或已裁判。FY2027 等财年名称本身不证明使用了未来信息。
6. **数字同时核对期间和口径。** 每个重要数值核对公司/分部、自然年或财年、季度、单季或累计、实际或指引、币种、单位、GAAP/非 GAAP，并定位原表行列或电话会段落。禁止将上一年 capex 指引拼到今年收入；未来重述值不能替代当时披露值。一致预期也必须有截至当时的版本。
7. **原始版本与修订版本分开。** 不倒填生成时间，不覆写原 Git 提交，不把事后重建文件当作当时可交易信号。补跑记录真实完成时间；修订记录发现日、旧说法、证据、更正、影响范围及原提交。历史图从该期冻结 JSON 生成，不能从今天的年度产品图回填。
8. **不凑数。** 头条最多12件，按核验后的实际数量发布并说明不足；零件时明确写“本周未发现可确认重大事件。”不能复制、拆分同一事项、挪用旧闻或越过截止日凑数。此规则依据用户 2026-09-08 的固定规则确认，替代此前“最多十件”；2026-09-09最新授权每家公司最多5条重要独立事项，先筛选再核证；头条只提炼入选事项，其余不必全部入详情。总行数/字符仍不设硬上限，保留入选事实、八字段、口径和限制，不用附录或打包绕过5条。

## 判定示例

| 情形 | 判定与处理 |
| --- | --- |
| 周日美东 20:00 公告，上海已是周一 08:00 | 超出本期，进入下一期 |
| 2025-11-03 AWS/OpenAI 380 亿美元公告写成 2026-07-01 新协议 | 旧闻错期，不是未来数据；撤销本周 new/strengthened 归类 |
| 7 月页面 8 月更新，仍清楚保留 7 月 9 日对应段落 | 只使用 7 月段落并记录位置，不借用 8 月新增内容 |
| 7 月公告 8 月上市或 2028 年机房启用 | 可写已知计划，不能写已实现结果 |
| Q2 数字到 7 月才公布 | 不能进入 6 月末截止的报告 |
| 文件名为周一，周二才生成或周五补跑 | 不是周一开盘前可用版本；新闻是否越界另查 |
| 财报晚更正，旧网页现在显示重述值 | 保存原披露值；更正从更正公开日生效 |
| 来源仅有日期，无时分或时区 | 保留原精度；未知时区按下述完整全球时间区间判断，不能伪造午夜时间；区间跨周边界仍须补证 |

不要根据今天检索到的最早结果声称已经穷尽所有更早披露。审计结论分为：已证实越界、可得性尚不确定、旧闻/数值错误、有证据支持期内公开。

## 日期精度不足

2026-09-08用户确认以下为固定规则：原文有明确公开日期、没有时区时，允许保留全部可能时间，不再为周中日期反复寻找无关紧要的精确时分。这不适用于仅有事件日期、URL日期、搜索摘要日期或无法定位所用正文版本的材料。

- 对原始日期D，按全球合法时区UTC-12至UTC+14，可能公开区间为 **[D前一天10:00 UTC，D后一天12:00 UTC)**，共50小时。上下界是数学边界，不是实际公开时间；不得任选一个端点填成`claim_first_public_at`。
- `news`须整个区间位于本期`[start, cutoff)`；背景、预测和判断的事实输入也须整个区间早于排他截止。不确定区间跨周边界就继续补证；不能只取与本周重叠的部分，不能通过换分类把旧闻当本周新增。
- 已知时区或精确发布时间的证据继续保留原精度，不主动丢掉信息改用宽区间。来源无日期、具体段落可能后加、未来更新无法隔离、重大断言未核清时仍不放行。
- 已知发布地或法院所在地也不授权伪造23:59:59。校验器会拦截“精确秒数”与说明中“日末/最晚时刻保守界”自相矛盾的记录；这只是已知错误模式检查，不能代替真实发布时间取证，亦不能通过删掉说明过关。
- 区间证据记录原日期、固定边界、时区未知说明及具体版本定位；机器重算边界、检查完整区间和抓取/复核时序，原文真实性仍须实际核验。正文显示原始日期和精度说明，不装作知道上海精确发布日期。

## 工作顺序

1. 读本规范、模板、上期报告及冻结状态；确认 D 和截止点。历史任务先查 Git 版本，不能以文件名推定可得时间。
2. 建立候选事实清单，找每个断言的首次公开依据；查媒体是否仅转述旧公告。来源受限时保留限制并补源，不把标题当全文。
3. 重要数字核对原表行列；网页更新拆分断言；未来计划保留预测语气。不能确认者进入 `excluded_candidates`，不混入已确认正文。
4. 写正文和状态。头条、公司表、详细事件、行业判断、催化和供应边共用已核事实，不能只检查供应图。
5. 运行 inventory，逐项建立时点证据。一条事实可关联多处；一处含多个独立断言时必须拆成多条 claim，不能拿一个来源为整段背书。
6. 完成财务口径、网页版本、产品图和报告版本四项语义复核，写具体核查点，不写空泛“已核对”。这里的人工复核是实际阅读原文的研究步骤，可由代理执行，不要求用户逐条签字。
7. 正文初稿及修改后先做只读格式预检（见 `context_efficiency.md`），不能靠删除重大事实过关；最终正文绑定证据后先过时点闸门，再生成图、跑来源审查、主闸门和测试。预检不授予事实资格，所有证据标准不变。只有当前任务已有发布授权且全部通过时提交推送。

## 机器证据契约

自 **2026-09-14** 起，必须有 `logs/YYYY-MM-DD_temporal_evidence.json`。更早周报若含 `<!-- point-in-time-policy: 1 -->` 或已有证据文件，也必须验证。旧报告缺失只能返回 `legacy_unverified`，绝不补造当时已核验的记录。

```bash
python3 scripts/validate_point_in_time.py --report reports/YYYY-MM-DD_weekly_morning_brief.md --baseline state/supply_graph_baseline.json --inventory
python3 scripts/validate_point_in_time.py --report reports/YYYY-MM-DD_weekly_morning_brief.md --baseline state/supply_graph_baseline.json --product-graph state/product_relationships_YYYY.json
python3 scripts/run_quality_gate.py --report reports/YYYY-MM-DD_weekly_morning_brief.md
```

长稿可给inventory命令追加 `--inventory-output logs/YYYY-MM-DD_inventory.json`，完整清单直接落盘，只返回目标数。已有文件不会被覆盖；不要把终端截断结果当作完整清单继续绑定。

`--inventory` 只列待核目标，不生成日期或“通过”。目标包括 `headline:N`（零件时为 `headline:none`）、`company:公司名`、`event:N`、`analysis:N`、`catalyst:N` 和当周变化的 `supply:EID`，必须全部覆盖。“无重大变化”也是截至当时的检索判断，须交代检索范围，不能声称穷尽事实。

顶层必填：

| 字段 | 含义 |
| --- | --- |
| `schema_version` / `report_date` | 固定 1 / 周一 D，YYYY-MM-DD |
| `cutoff_exclusive` | D 的上海 00:00，如 `2026-09-14T00:00:00+08:00`，不含该时刻 |
| `report_sha256` / `baseline_sha256` / `product_graph_sha256` | 当前三个文件的 SHA-256；变更后重新复核绑定，不能只改哈希冒充复核 |
| `report_created_at` / `reviewed_at` | 当前待审版本实际创建、实际复核完成的带时区时间，不是文件名日期，也不是首次发布证明 |
| `manual_reviews` | 四项各含 `status: reviewed` 和具体 `note` |
| `claims` | 原子断言列表 |
| `excluded_candidates` | 可选；记录排除断言、来源、原因，不会使正文中的未知项过关 |

四项复核：`financial_periods_and_units`、`source_versions`、`product_graph`、`report_vintage`。产品图须逐项核对新增/变更节点和 P/PX 边的公开日期；沿用项注明冻结版本和弱证据限制。机器尚不逐条理解产品图语义。

尚在整理的证据另存暂存路径并显式写 `status:draft`，不得覆盖正式证据。校验器拒绝draft，即使字段、目标数量和哈希已经齐全。自动整理的目标映射不是原子断言完整性或四项语义复核；只有实际复核后才能写ready。旧证据未含status字段时仍按原完整契约核验，不因此获得豁免。

每条 claim 必填 `id`、`statement`、`targets`、`kind`、非空 `evidence`；可填带时区的 `event_at`：

- `news`：断言首次公开在覆盖周内；新增/强化/弱化/风险供应边必须归此类。
- `background`：旧信息延续，正文必须明示背景，不能借分类绕过本周新增要求。
- `forecast`：截止前公开的未来计划，只有此类允许截止后的 `event_at`。
- `analysis`：研究判断；所有事实输入仍须截至当时可得，记录证据和推断，不用分类掩盖未知事实。

每条 `evidence` 必填：

- `url`：HTTPS 原始来源或权威媒体。新进展的证据须针对该进展，旧背景另设 claim。
- `claim_first_public_at`或`claim_first_public_interval`二选一：前者为**该断言**首次公开的带时区时间，不是网页创建日；后者按“日期精度不足”记录完整区间，不能同时填写或用端点冒充发布时间。
- `retrieved_at`：实际读取时间，可晚于截止，但不能单独证明截止前可得。
- `basis`：`dated_release`、`dated_section`、`archive`、`filing`、`dated_media` 之一。
- `locator`：公告日期及对应段落、更新小节、PDF 页码/表格行列或监管文件编号。
- `support`：简短说明断言及日期如何得到支持，区分公司陈述与独立确认，只保留必要短摘录。
- `page_modified_at`：能识别则记录。晚于截止时，须用 `dated_section`、`archive` 或 `filing` 证明所用版本。

日期区间的机器结构（示例仅说明格式，不作为真实来源证据）：

```json
{"claim_first_public_interval": {
  "published_date": "2026-09-03",
  "earliest": "2026-09-02T10:00:00Z",
  "latest_exclusive": "2026-09-04T12:00:00Z",
  "timezone_basis": "global_utc_minus12_to_plus14",
  "version_locator": "明确发布日期及所用正文段落/对应版本",
  "note": "原文仅日精度且时区未知；端点为完整可能范围，不是实际发布时间"
}}
```

其余来源字段、逐条目标、四项复核和报告哈希契约全部保留。版本定位缺失、边界缩窄或移动、同时声明精确时点、区间跨截止均不通过。规则修改单独计量，不将修改收益回算到已冻结对照实验。

哈希绑定、日期比较和目标覆盖仅验证**记录一致性**，不能自动证明来源语义、首次公开时间填写正确、原子断言拆分完整或数字真实。禁止把机器通过写成“保证不存在未来数据”。

## 断言与更正传播

每批材料在写作前按现有契约核对主体、事件身份、来源版本、公开时点和字段类型；解释文字写locator/support等说明字段，不代替basis枚举。实际取得/恢复核读时间取真实操作回执，不按批次估算或事后填整分。未知字段保留待核，不能为了构造合法JSON补造事实。局部结构检查只帮助提前发现返工，不替代最终校验。

一段正文包含几个可独立成立的事实，就分别核验：财务数字连同期间/分部/单位/口径；交易金额区分股东对价、或有支付、留任计划和融资工具；产品名称、地区/账户限制、预览/GA、数据保留、价格脚注和后续撤回不得在摘要中丢失。证据不同或时间不同则分claim，不能以“有一个来源”支持整段。法律程序须核主体、案号、申请/意见/裁判及程序阶段；媒体错误年份、通用产品标题或一份旧动议不能替代原文件身份。

更正时以稳定claim ID列出受影响的头条、公司表、详情、判断、催化和E/P/PX边，逐处核对删除、改写或降级；自动匹配只生成待审映射。保留更正前的字段/依据和失效原因。重新审查受影响事实与覆盖结论后，再绑定最终文件哈希；不能只改证据日期、只改详情漏掉头条图谱，或只更新哈希。段落全部有映射也不证明其中独立断言全部有证据。

## 历史修订与回测

- 原报告、状态、来源日志从 Git 读取并保留；审计单独保存，不将本次抓取时间倒填为历史审查时间。
- 更正记录发现时间、原报告/行号/提交、原值、新值、来源日期、更正公开日及受影响判断/边。应用展示版修订前标明“事后修订”；原样本与修订样本不能混合回测。
- `historical_snapshot_map.json` 是重建定位，不是实时可得性认证。8 月 26 日迁移产生的指标、判断和头条编排不是原周一的实时输出。
- 交易时点必须晚于实际可访问的报告版本。Git 首次提交只证明仓库已留痕，不证明此前没有本地草稿，也不证明已经推送到远端。
- 固定 Git commit、输入哈希、真实生成/修订时间及发布回执。不能预填尚未产生的 commit；发布回执另存，避免回写报告产生循环哈希。
- 缓存降级只缓解网络问题；同 URL 的旧成功不能继承给新内容版本或新断言，更不是历史网页快照。

上下文减重仅改变材料装载方式，详见 [上下文与缓存输入控制](context_efficiency.md)。索引、摘要、文件哈希和上期结论不增加证据资格；完整字段/日期/财务脚注不能为省 token 被裁掉。入选断言的逐条证据和四项语义复核不豁免；发现范围按最新有限筛选契约，信息缺失时扩读原始版本。

历史定点纠错与全量认证分开：2026-09-14 之前的遗留报告，可在用户明确要求替换后保存归档、逐项 `correction_evidence` 和版本登记，再替换展示路径；没有完成全部时点取证时仍为 `legacy_unverified`，不得生成虚假的全量通过记录。这不是未来新报告的豁免。只补版本标识的其他期次，不声称新闻内容已重新研究。

纠错版本用 `<!-- report-vintage: revised -->` 标识，登记在 `state/report_vintages.json`，绑定原提交、替换前/当前哈希、归档哈希和真实修订时间。`scripts/validate_report_vintage.py --report reports/YYYY-MM-DD_weekly_morning_brief.md --for-backtest` 必须拒绝将修订展示版用作原周一输入；恢复原文也不自动取得回测资格，仍须核对原始发布回执。旧迁移脚本不得覆盖已登记纠错版。

## 发布前四问

发现范围及覆盖闸门另按 `docs/research_coverage.md` 执行：有限筛选后对入选断言完成本规范核验。未入选不等于不重大或已核完；原子证据只证明已选断言，不证明未遗漏监管等事件。新增覆盖流程不得追溯算入已冻结的缓存优化对照实验。

1. 每个事实在截止前哪一天、哪个时区、哪份材料的哪一段已经公开？
2. 页面是否加入截止后内容？财报数字是否来自正确期间和口径？
3. 是否将旧闻、未来计划、媒体说法或今天的修订当作本周已发生事实？
4. 报告当前版本实际何时可用？哪些仍无法确认，是否保留限制？

任何一问答不清，相关事实不按已确认新事件发布。修证据，不放松闸门维持“全部通过”。
