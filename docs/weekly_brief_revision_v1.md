# 周报修改办法 v1

2026-10-19用户授权后，唯一采集版本和信息截止均为周一上海09:00。按point_in_time_policy保留实际取数时间、过渡期和历史原稿；每日行情仍只含截止前已完成交易日。

制定：2026-10-10。用户已要求实施两套设计审查中的优化。本文是执行办法，不是新一期周报、交易信号或收益验证。

## 1. 目标与取舍

从“发生了哪些新闻”改为“公司发生了什么重要变化、可能通过何种渠道影响投资、市场已经出现什么变化、下一步如何证伪”。目标是提高决策可用性；不能为提高表面相关性倒选新闻，不能预先承诺提高收益预测能力。

采用**市场反应台为基础、投资假设簿为有限扩展**，而不是立即把全部新闻变成交易预测。保留12家公司、每家0-5条独立事项、最多12条头条和八字段证据。新闻官方入口及独立重要性校准不减。事实、PIT和历史回测细则的唯一正文仍为[时点规范](point_in_time_policy.md)，选题细则仍为[覆盖规范](research_coverage.md)。

工程默认从2026-10-12期启用，历史期不自动改稿或追加预测资格。v1每期最多3个可证伪投资假设，可以为零；这是控制成本的实现默认，不冒称用户逐字指定。修改默认参数必须登记新版本，不能追改已冻结样本。

## 3. 内容与UI

### A. 市场反应台

首屏顺序：报告期与排他截止、市场数据完整性、12家公司市场表、少量投资假设；新闻详情和产业链证据在后。无巨幅宣传头图、不用涨跌颜色代替判断、不按本周涨幅默认排序。

市场表固定公司顺序，包含直接证券/币种/基准、本周总回报、相对基准回报、RV20、RV20周变化、周内冲击、实际交易日数、最后收盘时点、入选事件ID、缺口与限制。按2026-10-10用户最新要求，仅面向桌面端，不开发手机端应用或专用界面，不做手机适配、断点、截图、测试与验收。桌面窗口内的长表可独立横向滚动，不挤压或裁掉公司名和限制。静态Markdown保证电脑上的GitHub可读；HTML提供锚点与证据折叠，不要求服务器，不自动刷新历史页。

v1不画精确事件竖线或“新闻贡献了涨幅的X%”。只保留具有时间精度约束的关联说明，列同时发生的行业、利率、汇率、财报等其他解释。未来添加价格曲线时，区间时间只能画阴影范围，未知时间不定位；当次没有入选来源支撑的宏观解释只能是待验证解释，不能补写成第六条事实。

### B. 投资假设簿

每条假设展示：稳定ID、已入选事件、价格方向观点、独立的波动观点、预期基线类型与证据、业务到财务的传导、财务量级与分母、兑现窗口、证伪条件、其他解释。

财务量级尽量写“对应年度/分部收入、利润或FCF的约X%-Y%，基于哪些假设”；不可量化时写明缺失的订单、利润率或分母，不凭新闻语气猜目标价。方向观点不是买卖指令，利好公司不等于本周股价上涨。业务兑现窗口可以远长于固定统计观察窗口；两者分别说明，5日未上涨不直接证伪长期业务判断。

不显示未经校准的置信概率、目标价或仓位。无可靠预期时只能标“研究假设/未知”，不写“超共识”“尚未定价”。供应链图只解释已有入选关系，不自动将非上市公司变化换算成合作方股价敞口。

### C. 后验复盘

另建后验文件/页面，醒目标“事后观察”，链接原快照、哈希、实际发布回执和评价政策。冻结页不内嵌后验数值、命中率或今日价格。v1仅落实隔离与预注册，不提供自动交易或成熟的业绩评分系统。

## 4. 市场口径

2026-10-19显示整改（输入schema v2）：保留下表的v1合格总回报定义和预注册评价不变；另外允许隔离的当前版本价格观察。新增“回报口径／数据版本”，实际股票代码、币种、当地基准、本周价格回报、相对价格指数回报、价格RV20及周变化/冲击、真实交易日/收盘样本、末次收盘均由真实回执计算。未计分红须明确标成价格口径；历史PIT未认证不伪装成样本不足。单一基准缺失只影响相对回报，不能清掉个股指标。未建立直接证券映射的公司标不适用。精确资格与隔离边界只维护于PIT规范。

本次按用户指示登记：7家纳斯达克上市股→IXIC.GI，三星/SK Hynix→KS11.KS，台积电台股2330.TW→TWII.TW。韩国旧KS11.GI被API标退市，不沿用该身份；台湾日历为TWSE，不能误用TSE。本期没有日本上市证券，不虚构日本样本。代码入口为`scripts/download_wind_market.py --report-date YYYY-MM-DD --execute`及`scripts/normalize_wind_market.py --manifest PATH`；原件按次新文件，合格数据后才进入观察快照。直接输入框架及显示资格与PIT能力分开，不要求用户手动执行查询。

| 指标 | 固定v1定义 | 边界 |
| --- | --- | --- |
| 本周总回报 | 本周真实交易日的 `product(1+r)-1` | 本币、同一直接证券；分红/拆股仅使用截止前可得调整 |
| 超额回报 | 个股本周总回报减同币种同期基准总回报 | 非beta调整alpha，不证明因果；基准事先固定 |
| RV20 | 最近20个日对数收益的样本标准差乘 `sqrt(252)` | 需要20个收益即至少21个对应收盘价；不足则空缺 |
| RV20周变化 | 本周末RV20减上周末RV20 | 单位为百分点；旧冲击移出也会使其下降 |
| 本周冲击 | 本周日对数收益均方根乘 `sqrt(252)` | 未去均值的历史冲击，不称为预测或与RV同义 |
| IV | v1不强制采集或显示 | 后续须固定期限、价内外程度/Delta、买卖报价与快照时点；缺历史版本就不补 |

`r`为简单总回报，内部用小数（0.01表示1%），不是百分数字符串。绝不把未交易日填零、不跨时区强行拼接、不将停牌/无数据当零波动。25个有效日收益通常足够比较两个20日窗口；节假日以实际交易日数为准。自动计算只检查结构，交易日历完整性、供应商口径、公司行动、币种、原始到标准化转换仍需人工复核。

2026-10-19专项实现：现金事件诊断采用税前现金在除息日收盘再投资，公式/实际差异与三地总回报接口见Wind取数契约；该诊断保留“仅已确认事件”的覆盖限制，不放宽上表合格总回报定义。价格与分红标准化后自动冻结，具体时点规则仍只维护于PIT规范。存储与容量实测见`weekly_data_storage_plan.md`，不以归档设施上线代替真实PIT认证。

直接证券、交易所、币种、日历和基准第一次接入时登记；以后沿用，变更必须记录，不能在看完结果后切换ADR/本地股或基准。OpenAI、Anthropic等若没有可核独立上市序列，标未映射，不虚构自身股价，也不用合作方股价冒充。缺某家公司行情不删除公司或其重要事件。

## 5. 预注册评价

以下是v1工程默认，不是已验证最优参数：

- 价格观察：实际可访问发布时点之后，目标证券首个常规交易时段开盘开始，到第5个交易日收盘的总回报，减同期可比基准回报。若延迟发布或中途修订，不能按名义周一提前入场。
- 波动观察：同一入场开盘到第20个交易日收盘，首日用开盘至收盘，其后用收盘至收盘，共20个对数收益，样本标准差乘sqrt(252)；与截止前RV20基线比较并披露首日口径差异。不能把入场前隔夜收益混入结果。同期无观点公司照样保留。
- 主要基线：零超额回报、维持截止前RV20；价格方向与波动方向分别评估。对未作方向预测的样本标abstain，不计成功、不当作看平。定性判断只报告方向结果和覆盖率，不伪造回归IC。
- 完整样本账保留12公司每期、未选事件、无观点、数据受阻、未成熟观察和失败。披露分母、可评估样本、缺失原因与同周跨公司相关性；样本少时只作描述，不宣称统计有效。20日窗口跨周重叠，不能当独立样本计算显著性。
- 禁止根据结果改窗口、换基准、删失败样本或倒改原预测。试验过的政策版本全部保留。更复杂评价须前瞻登记并采用时间外检验，不为短期漂亮相关性继续调参。
- v1不报告策略收益、胜率承诺或仓位建议。未来若启用策略评价，另固定执行价格、交易成本、滑点、冲击、可交易性、资金与持仓规则，并处理退市及幸存者偏差。历史补写只能做描述性回放，不能冒充前瞻验证。

后验结果另存 `logs/YYYY-MM-DD_investment_outcomes.json`：须绑定原快照哈希、政策版本、回执路径/哈希、实际delivery_at、每证券实际入场/出场、原始观察版本、状态（pending/evaluated/abstain/missing）、完整公司分母及限制。当前没有自动结果评分器；人工核验不伪装成已通过自动回测。

## 6. 数据与成本

本机Wind API执行方式见[Wind取数契约](wind_api_workflow.md)，由skill和手册共同引用；同一会话、非空对照、分市场日历、原件回读及失败停止是取数要求，不增加或放宽本办法及PIT规范的数据资格。

分红字段空值恢复可由登记市场的官方备用API补充，`download_dividend_events.py`统一下载，`dividend_events.py`记录逐事件/逐字段结果及真实provider。该接口目前实测覆盖7家US证券现金事件，不能将恢复金额/明示除息日的成功，直接当作完整公司行动或历史价格版本认证。韩国、台湾与未上市样本的处理边界见Wind取数契约。

先复用合格的已有具体版本。首次行情接入只试一个合格来源与一个明确备用来源；在本期停止时记录 `unavailable` 和恢复条件，不为补行情重启新闻泛搜、不自动购买数据、不索要已确认不存在的文件。日线与直接证券优先，历史共识和期权属可选增强。

日线若只有今日重新复权版且无法证明历史版本，不能包装成历史PIT数据。v1工具仅接受已落盘、可复核的输入，不内置有账号/授权假设的数据订阅。本次设计预览没有采集行情、没有运行本期新闻研究、没有投资预测，不可用于实盘或历史绩效。

完整token总账继续按生产、额外补证、维护、失败返工分阶段。单次读取同一冻结JSON即可产生两种显示，不重复研究、复制事实账或为UI再搜一轮。

## 7. 实施接口与验收

新期正文增加 `<!-- investment-review: 1 -->`，兼容schema v2。在原第1节之前增加“第0节：市场反应与投资假设”，由 `logs/YYYY-MM-DD_investment_review.json` 生成 `investment-review:start/end` 区块；不能手改数字后只更新哈希。原第1-7节、公司表及八字段保留，避免破坏原逐条时点证据目标；投资模块用单独契约核验，并绑定同一入选名单，不是免核区域。

JSON精确字段与反例见 [`scripts/investment_review.py`](../scripts/investment_review.py) 和 [`tests/test_investment_review.py`](../tests/test_investment_review.py)。设计预览样本位于 [`examples/investment_review_v1.json`](../examples/investment_review_v1.json)，只演示缺失态，不能改kind就发布。

生产快照绑定唯一coverage文件的路径、筛选语义哈希及每家入选ID；来源字典保存本地完整版本、哈希、URL、availability、retrieved_at、版本、定位及可得性依据。availability复用PIT的 `claim_first_public_at` 或完整 `claim_first_public_interval`，不将区间端点伪装成发布时间；关联时间与所引来源必须一致。市场来源文件采用 `{instrument, sessions}` 标准格式；原供应商响应须另归档并在locator/可得性依据中关联，标准化不是原件。所有衍生指标由脚本计算，不接受手填统计量。来源哈希和时间字段不证明来源真实，原文与转换须人工逐项复核。

操作顺序：有限筛选与冻结名单；接入有版本的行情并独立观察；选择0-3条假设；生成投资快照及区块；正文只读预检；绑定temporal/coverage最终哈希及人工语义复核；投资校验；图与来源审查；原完整闸门。若改变名单/假设/行情，重新生成区块并重新预检、核验和绑定，不能只换哈希。

不另建筛选摘录或复制事实账。`coverage.selection_sha256`绑定原coverage的 `report_date`、`selection_policy`、`company_conclusions` 和入选candidates，按脚本的规范JSON序列化计算；不纳入coverage的report_hash等输出字段。最终coverage仍由原全闸门绑定整篇正文；投资区块自身再绑定快照文件哈希，避免循环。

```sh
python3 scripts/investment_review.py --snapshot logs/YYYY-MM-DD_investment_review.json --markdown PATH_NEW.md --html PATH_NEW.html
python3 scripts/validate_weekly_brief.py --preflight-only --report REPORT --baseline BASELINE
python3 scripts/investment_review.py --report REPORT
python3 scripts/run_quality_gate.py --report REPORT
python3 -m unittest discover -s tests -p 'test_investment_review.py'
```

输出文件必须是新路径；工具不覆盖冻结产物。设计预览另加 `--allow-preview`，正式校验拒绝preview。

验收分别报告：规则落地、反例测试、显示一致性、真实一期数据接入、前瞻效果。前三级完成不等于后两级完成。若合格市场数据不可得，允许原核证研究按原闸门发布，但全12家公司缺口必须显示，不能称“市场关联已验证”。入选事实缺口、错误来源版本、未来数据或已知矛盾仍不放行。

## 8. 方法参考
