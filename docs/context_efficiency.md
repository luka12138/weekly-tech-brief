# 上下文与缓存输入控制

多结果返回还需检查合计载荷：使用 `prepareToolBatch`，不能以各单项未超限替代整体预检。导航定位、range校验和动态推荐栏日期边界见 `tool_output_contract.md`。所有已发生的截断重读和失败重试仍计入本次总账，不因补上保护而回溯剔除。

2026-09-07 起执行。用户要求降低缓存输入，但不牺牲每周周报的精度与真实性。本文件只管材料如何进入上下文，不改变[时点规范](point_in_time_policy.md)的任何证据标准。

## 目标与边界

减少不必要的上下文和无效模型往返，不追求降低缓存命中率。缓存输入是输入的一部分；禁用缓存或频繁改写固定前缀可能增加成本，不能当优化。[OpenAI 缓存说明](https://developers.openai.com/api/docs/guides/prompt-caching)。这里没有配置 API 缓存参数的权限入口，也不替换模型或降低推理设置。验收看整次实际输入、输出和覆盖质量，不以缓存占比升降单独评分。

skill 不能清除已经进入当前任务的历史，也不能保证控制应用的压缩时机。仍只保留一个定期执行任务；不以新建/切换任务、删除历史、改写会话文件绕过此限制。阶段记录用于可靠接续，不等于已经触发上下文压缩。

## 每次如何读取

1. 每次运行读当前 skill、时点规范、模板、手册操作流程和单一任务交接；本文件首次使用或变更时读。记录所读文件路径及 SHA-256；同一轮无需反复全文读取未变文件。上下文压缩后，若所需规则细节已不在可用上下文，必须补读，不能仅凭哈希声称记得内容。
2. 运行记忆只读最新完整条目；交接记录接续未完成事项。只有出现相关问题才定点读取旧条目、旧任务、旧审计。规则维护时核对 `rule_decisions.md`，其他运行遇到冲突时读取相关裁决。不能每周重新加载三个任务全部历史。
3. 读 `reports/latest.md` 指向的上一期正文一次，用于比较而非事实认证；先索引完整供应及产品基线，再按下面规则展开。审计/修订显式选择当期冻结文件，不默认读取今日基线。
4. 手册按当前阶段展开相关章节；首次完整执行、规则变更或无法确认已读内容时补读。不能用目录或摘要代替适用的执行要求。首次建立产品基线理解时，分批读完全部公司、主营产品和关系；以后沿用已读冻结版本仍保留证据限制。

## 基线：索引与完整记录

只读工具不修改 JSON，不提供事实认证，不按 `changed_this_week` 过滤记录：

```bash
python3 scripts/brief_context.py --file state/supply_graph_baseline.json
python3 scripts/brief_context.py --file state/product_relationships_2026.json
python3 scripts/brief_context.py --file state/supply_graph_baseline.json --expect-sha256 SHA_FROM_INDEX --pointer /edges/0 --pointer /edges/1
python3 scripts/brief_context.py --file CURRENT_FROZEN_JSON --previous PREVIOUS_FROZEN_JSON
```

- 索引列出每个集合的总数、每条记录的位置/标识与证据等级等字段，保留顶层限制说明；`fields_requiring_expansion` 明示未显示字段。索引不是正文摘要，更不是已核验证据。原始完整资料不删除。
- 展开必须绑定索引的完整 SHA-256，返回所选记录全部字段，包括来源、财务口径、注释、限制和未知新字段。哈希变了就重新索引并复核差异，不把旧位置用到新版本。
- 差异比较覆盖所有字段，输出新增、修改和删除记录的完整前后值；排序变化会保守地列为变化。结构变化不等于本周新闻；上期 `new/strengthened` 不能沿用为本期增量。
- **必须展开**所有新增/修改/删除项、涉及当周候选与正文判断的关系、关联公司的产品链、低等级/未知/争议证据及来源受限项。索引未展示的限制不视为不存在。无可靠已读基线、首次使用或展开范围无法界定时，分批读全量，不能为省 token 漏掉核验。
- 每期仍检索全部 12 公司，并对全部主营产品及关系索引做覆盖检查。产品图四项复核中的沿用项须绑定冻结版本并保留弱证据限制；未完成历史核验的项目不能因“内容没变”升级为已确认。

## 来源与工具输出

- 已采用方案二：入口按 `research_source_routes.md`，去重与事件工作卡按 `research_coverage.md`。请求前先查已有材料和未解问题；已核同版本claim直接复用，只有新范围、具体缺口、版本变化或矛盾才补请求。只差本地绑定/格式就转本地步骤。失败回退换有依据的入口，不原样反复打开同一失败页；不新增方案三的自动采集系统。
- 所有来源筛选和降耗方案都须保留各家公司官方渠道为每期必查来源，不能用媒体或聚合摘要替代；具体范围、受阻处理及复用边界见 [官方渠道保留](research_coverage.md#官方渠道保留)。减少重复读取，不减少官方信息覆盖。
- 返回模型前使用 `scripts/tool_output.cjs` 检查返回类型并选择有效内容；首次接入、工具形状变化或失败时读 [工具输出契约](tool_output_contract.md)。返回字符串时不枚举其键；未知结构用专用适配器，不能盲目倾倒调试。输出大小按字符标明，不伪装成实测 token。
- 必须联网。按公司/主题批量检索并合并同一事件的重复报道；批处理减少模型往返，不限制入选事项必要的补证深度，但按最新每家公司最多5条口径冻结名单。只按实际返回且检查过的公司/业务验收，空结果或被别家公司占据的结果须定向补查。每批结束即增量写入research_coverage.json，避免压缩后重新找候选或凭回忆补账；无合格入选项也如实记录该公司官方筛选及独立重要性校准，不宣称已穷尽。
- 同一轮已经实际读过的同一来源具体版本，可通过原子 claim ID 在多处引用；保留 URL、首次公开时间、实际读取时间、定位、必要短摘录和版本依据。不把搜索摘要、旧报告、运行记忆或模型摘要当原始证据。重新访问同 URL 时核查是否变更，不能继承旧成功。
- 页面先定位有关段落、完整表格和脚注，排除导航及无关推荐；表头、期间、单位、分部、实际/指引、否定语气、限定条件和修订说明不得裁掉。节选无法确认口径或日期时必须扩读原文；不要用固定字符截断代替判断。保存允许留存的原始材料或必要证据摘录，不绕过付费墙，不把受保护全文提交到公开仓库。
- 工具只返回当前需要的内容。通常状态输出控制在约 2,000 tokens 内，原文核验按完整语义分块，不设研究总 token 硬上限。超长结果落本地日志并回传路径、退出码、计数和全部失败/限制定位，再逐项展开；不能靠 `head` 隐去失败，也不能把输出被截断当作已读。
- Canvas/SVG 和完整来源审查 JSON 由脚本读取处理，模型看生成计划、差异、统计、失败项及实际图像，不反复倾倒图形源码或全部 HTML。测试通过时报告摘要，失败时读完整相关诊断。能在一次工具调用内顺序完成的独立读取/校验可合并，前序失败必须停下处理；不能减少实际校验次数或绕过依赖顺序。

## 格式先预检

初稿完成及正文修改后，先运行：

```bash
python3 scripts/validate_weekly_brief.py --preflight-only --report reports/YYYY-MM-DD_weekly_morning_brief.md --baseline state/supply_graph_baseline.json
```

复用完整校验器的头条、公司范围、事件字段、催化、附录及篇幅规则；只读正文和指定基线，无需来源日志、逐条证据或图像已经生成。历史工作须指定冻结基线。旧结构只做有限预检，不转换历史格式。通过后按原规范完成时点绑定、图谱、来源审查和完整闸门，事实/URL/正文变更仍使原哈希认证失效。`run_quality_gate.py` 的例行路径已在这些工作之前强制预检；历史只读路径保持原完整验证。

2026-09-09最新口径先按重要性筛选每家公司0-5条，不要求全部新闻进正文；入选事项不得删期间/单位、脚注或不确定性。总行数/字符仍无硬上限，头条最多12件且只提炼入选事项，八字段与事实证据标准不变；其他规则确有实质冲突时留草稿询问，不自行取舍。解决格式问题后再核研究覆盖闭环、进行完整来源审查，不以复用过期审查日志省开销。

## 分阶段计量与完整总账

`logs/YYYY-MM-DD_token_phases.json` 只记运行ID、带时区的起止边界及阶段，不复制会话正文。开始工作时确定总账起点，在已有工具调用里记录实际阶段切换，不为打点额外发起模型往返；补记边界只能有实际日志依据。阶段可多次进入：

- `production`：例行研究、正常取证、撰写、校验、发布，包含为完成它发生的格式返工；正常取证不能为了美化生产数据全部划出去。
- `evidence`：明确追加的专项补证/遗漏复查；与生产混合且无法拆分时不猜分。
- `maintenance`：skill、脚本、规则和测量设施维护，含相关失败重试。
- `unclassified`：工具自动保留未标记、跨阶段、边界和无法拆分的增量，仍进入总账。

最小清单示例（时间只是示例，不能照抄为执行记录）：

```json
{"run_id":"2026-09-14-weekly","start":"2026-09-14T09:00:00+08:00","end":"2026-09-14T10:00:00+08:00","phases":[{"name":"production","start":"2026-09-14T09:00:00+08:00","end":"2026-09-14T10:00:00+08:00"}]}
```

```bash
python3 scripts/measure_run_tokens.py --session /ABSOLUTE/PATH/TO/SESSION.jsonl --manifest logs/YYYY-MM-DD_token_phases.json --output logs/YYYY-MM-DD_token_ledger.json
```

脚本只读原会话，输出文件必须为新路径，禁止覆盖冻结实测；阶段不能重叠。总账包含时间窗口内所有去重后的累计用量增量，不按任务ID筛掉维护或返工。同模型/设置信息从会话读取，原始增量逐项保留，每阶段相加等于总计。缺少起点之前的计数则拒绝伪报完整；遇累计重置留标记，异常单字段倒退报错，未知可选计数用 null 不用0。

计量先识别日志版本和累计范围。`token_usage_record`使用`thread_token_usage`，不能把单次`usage`或`turn_token_usage`当全账；同文件并存旧`event_msg/token_count`时默认优先线程累计，不能交替相减或两套相加。保留可用记录数、采用范围、真实末次时点；新格式缺累计字段、同response冲突、线程范围改变或倒退均报错，不静默漏计。只有旧格式时保留原重置处理。`counter_format:legacy_total_token_usage`仅用于复现旧冻结账；与线程累计不一致须另建对账记录，不能覆盖旧账或把较小数字冒充完整耗用。新格式起点无基线则拒绝认证，不自动拼接不同范围。

同时报告 requested 起止、实际 counter_baseline_at 和 last_included_token_event；边界落在两个计数之间时首笔保守列未归类，不能声称精确按秒切开。末次落盘后尚未计入的输出标明待结算，不能当0或称已计全最终回复。总账按事件时间分摊，不声称是逐工具因果成本；不同阶段复用的旧上下文仍按实际计数保留。

对外同时列总账和阶段账，不能只展示较省的生产阶段。比较同模型/设置、相同证据标准与相近工作量，列用量增量事件数、每事件平均输入、input/cached/non-cached/output 和未知项；它们不是HTTP请求数或费用。测量数据不可取得就如实写不可得；历史冻结9/7对照不重算、不扣失败、不套用新增规则。新工具正确性测试不等于已证明下一期降耗。

## 接续与验收

机械来源审查因瞬时网络故障中断时，可用 `run_quality_gate.py --resume-source-audit logs/已冻结的本轮审查.json` 续验。只复用15分钟内、正文/两类基线哈希、URL清单和claim定义全部未变的成功检查；失败项重新请求，相关claim重新检查。原审查先冻结到新文件，续验记录其哈希与复用项；不得把失败改成功、覆盖失败原件或用此功能替代时点/语义复核。TLS或握手超时可用另一HTTP客户端补一次真实状态读取，保留前次错误；401/403/429不借此绕过访问限制。跨期或输入变化仍须完整审查。

先区分本次是例行生产、指定补证还是规则维护，按最新用户要求继续，不因“还有旧待办”就自动重跑周报或扩大维护范围。每批来源处理后完成可执行的本地保存/字段/引用检查，只差本地绑定的不再联网；不要累计数十条明显格式错误到最后一次性返工。有限筛选及入选核验完成就停止；旧候选、未选业务、全部活跃事项没有清零要求，不因新线索重启泛搜。

中断后先读最新有效检查点和实际文件，核对当前阶段、未落盘结果及仍运行命令；不能把进程列表、全部原始日志或多版旧进度全部倾倒进上下文。更正后的最新结论只维护一个入口，旧检查点保留并标历史。阶段完成须有相应产物/检查回执，不能把“已写规则”“已做结构映射”当研究完成。

研究、成稿、发布发生实质阶段变化时，在 `logs/YYYY-MM-DD_working_checkpoint.md` 更新一份短执行记录，不把它重复全文贴入聊天。保留：覆盖周/截止点、12 公司检索完成与缺口、原子证据文件及 claim ID、已读基线/规范路径与哈希、变更与排除理由、未决问题、下一步、实际校验和发布回执。限制不能为缩短摘要被删掉；详细证据通过文件定位接续。

记录只保存确实完成的步骤；文件或来源变更、日期跨期、压缩后无法恢复原文核验依据时，重新展开相关材料并核查。沿用项可避免重复传输原文，但不能替代本期检索和证据契约。自动化 memory 每次只追加一个简短最新条目，指向交接/执行记录，不复制完整报告和所有历史；旧条目保留，最新状态不能悄悄丢失未完成事项。

验收必须同时满足：

- 12家公司保留，每家最多5条，不凑数、不承诺零遗漏；入选事项必要的直接来源和交叉验证要求不变。新旧研究范围不同，不冒称同口径token降幅。
- inventory 全目标覆盖、原子断言、首次公开时间、财务期间/单位、四项语义复核、历史版本隔离、来源审查、图形检查、主质量闸门和相关测试全部照常；不缓存跨期“无变化”结论或复用过期通过日志。
- 统计同一运行实际 `input`、`cached_input`、`input-cached_input`、`output` 和用量增量事件数；推理量若包含在 output 不重复加算。有 cache-write 统计则另列，不把 token 数直接当费用。总账不扣审计、维护或返工；纯生产对照另列相同阶段，同时披露总账和范围差异，仅对同模型/设置、相近新闻量及相同证据标准作可比判断。数据不可得就写不可得。
- 用字符/字节数比较工具输出时明确是局部载荷，不冒称整期 token 或费用降幅。第一次优化后的完整周报尚未完成前，不承诺节省比例。出现覆盖/核验下降时回退到完整分批读取，而不是放松规则。
